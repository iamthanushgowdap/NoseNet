# NoseNet — IoT-Based Cake Freshness and Adulteration Detection Platform

**College Capstone Project**: *“IoT-Based Cake Freshness and Adulteration Detection Device”*  
**Architecture**: Local-First • Zero Cloud Database Dependency • Swappable Storage Adapter Pattern

---

## 1. Project Overview

NoseNet is a scientific monitoring platform and sensory assessment terminal designed for laboratory testing of bakery products (normal sponge cakes, cream-filled pastries, refrigerated and frozen samples) using an IoT electronic nose powered by an ESP32 microcontroller and metal oxide semiconductor (MOX) gas sensors (BME680 / MQ series).

### Core Philosophy
- **Local-First & Resilient**: Functions entirely offline without Supabase, Firebase, cloud databases, paid external APIs, or mock endpoints.
- **Academic Transparency**: No fabricated statistics, simulated neural network weights, or artificial accuracy scores. AI freshness classification is intentionally marked as unavailable until a peer-evaluated model is trained on calibrated datasets.
- **Extensible Architecture**: Code is decoupled behind domain services and an `IStorageAdapter` interface, allowing a seamless transition to PostgreSQL / WebSockets in Phase 2 without rewriting any frontend components.

## 3. What Works Locally vs. Phase 2 Backend Roadmap

| Feature Capability | Current Local-First Version | Phase 2 Production Backend |
|---|---|---|
| **Data Storage** | Browser `localStorage` with JSON serialization & quota protection | PostgreSQL database with Prisma ORM |
| **Authentication** | Local demo sign-in (Researcher vs. Assessor roles) | Secure JWT / Session cookies with bcrypt password hashing |
| **Two-Phone Synchronization** | **Device-isolated**: Data is preserved within each phone’s local browser | **Real-time synchronized**: Shared WebSocket / MQTT broker relays assessments across phones |
| **ESP32 Data Ingestion** | Local CSV drag-and-drop & file upload with live validation preview | ESP32 Wi-Fi / MQTT publishing directly to backend REST endpoint |
| **AI Spoilage Prediction** | Explicitly disabled: displays *"AI prediction unavailable — insufficient validated data"* | Scikit-Learn / ONNX runtime running evaluated classifier trained on 200+ paired runs |
| **Backups & Portability** | One-click JSON backup export and validated restoration | Automated database dumps & cloud S3 backup rotation |

## 4. ESP32 CSV Format Specification

The CSV import engine accepts logs generated by the ESP32 firmware. Column names are mapped flexibly and validated against the Zod schema.

```csv
experiment_id,sample_id,stage,sample_no,elapsed_seconds,temperature_C,humidity_percent,pressure_hPa,gas_resistance_ohm,gas_resistance_kohm,status
EXP-2026-001,SMP-NC-UF-01,ROOM,1,0,24.1,51.2,1012.5,54200,54.200,OK
EXP-2026-001,SMP-NC-UF-01,ROOM,1,5,24.1,51.3,1012.5,54300,54.300,OK
EXP-2026-001,SMP-NC-UF-01,EMPTY_CONTAINER,1,15,24.3,51.0,1012.4,52800,52.800,OK
EXP-2026-001,SMP-NC-UF-01,CAKE,1,25,24.5,52.5,1012.3,48500,48.500,OK
```

### Protocol Stages:
1. **`ROOM`**: Ambient background air calibration (establishes baseline resistance $R_0$ and detects environmental temperature/humidity fluctuations).
2. **`EMPTY_CONTAINER`**: Chamber cleanliness verification (ensures zero residual alcohol or volatile contaminants prior to cake insertion).
3. **`CAKE`**: Headspace volatile organic compound (VOC) response curve.

## 5. Cake Matrix & Storage Combinations

NoseNet explicitly supports and distinguishes all four required specimen combinations:
- **Normal Cake — Unfrozen**
- **Normal Cake — Frozen** (-18°C cold preservation)
- **Pastry Cake — Unfrozen** (Cream-filled, accelerated microbial degradation)
- **Pastry Cake — Frozen**

Statuses are kept strictly distinct without premature automatic tagging:
- `Planned` (Specimen registered, awaiting testing)
- `Testing` (Protocol currently executing)
- `Completed` (Sensory + sensor testing finished)
- `Invalid` (Specimen contaminated or test aborted)

## 6. Manual Assessment & Disagreement Tracking

The Assessor Terminal (`/assess`) provides a mobile-optimized interface with touch-friendly Grade buttons:
- **Fresh** (Grade A)
- **Average** (Grade B)
- **Not Good** (Grade C)

### Features:
- **Confirmation Modal**: Prevents accidental clicks before writing to persistent logs.
- **Sensory History Preservation**: Multiple assessments for the same cake sample are never overwritten.
- **Panel Disagreement Detection**: If Assessor A votes *Fresh* and Assessor B votes *Average*, the system prominently flags the disagreement while preserving both evaluations with timestamps.
- **Academic Disclaimer**: Clearly marks labels as human organoleptic evaluations, not laboratory microbial cultures.

## 7. AI Model Status & Scientific Mandate

On the AI Status page (`/ai`), the inference engine is kept in state **`Not Configured`** or **`Unavailable`**.
- Displays: *“AI prediction unavailable — insufficient validated data.”*
- Tracks dataset readiness progress (counts paired specimens that possess both valid ESP32 sensor time-series and confirmed manual sensory ratings).
- Explains confounding factors: MOX sensors exhibit temperature and humidity cross-sensitivity; gas resistance alone cannot confirm food safety without baseline normalization ($\Delta R / R_0$) and GC-MS correlation.

## 8. Getting Started Locally

### Prerequisites
- Node.js 18.x or 20.x or higher (Tested on Node.js v24)
- npm 10.x or higher

### Installation
```bash
# Clone or navigate to repository
cd NoseNet

# Install dependencies
npm install

# Run Vitest test suite
npm test

# Run ESLint check
npm run lint

# Compile production build
npm run build

# Start development server
npm run dev
```

Visit [http://localhost:3000](http://localhost:3000) in your browser.

### Quick Demonstration Dataset
On first load, click **“Load Sample Experiment Dataset”** on the dashboard or navigate to **Data & Backup (`/backup`)** and click **“Load College Dataset”** to instantly seed realistic Normal vs. Pastry Cake experiments, ESP32 sensor readings across all 3 stages, and sensory panel evaluations with disagreement detection!

## 10. Pre-Production Deployment Checklist

Before deploying NoseNet into an operational university food science laboratory:
1. **Deploy Ingestion Microservice**: Implement an Express/FastAPI server with MQTT broker (Mosquitto) to receive wireless ESP32 telemetry.
2. **Swap Storage Adapter**: Create `HttpStorageAdapter` implementing `IStorageAdapter` to save experiments into PostgreSQL.
3. **Train Classification Model**: Collect at least 200 paired batches, extract features ($R_{cake} / R_{0}$, rise time, decay slope), and train an SVM / Random Forest classifier.
4. **Independent Lab Evaluation**: Cross-reference sensor-based predictions against standard plate counts ($CFU/g$) and sensory panel tests.
